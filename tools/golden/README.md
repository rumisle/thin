# Golden-data generators

Generators construct inputs in code, then obtain outputs from thin's own API,
a native example calling internal core APIs, llvm-mc cross-checks, or explicit
GPU recordings. They must not open a checked-in `tests/data` file. Only the
comparison layer opens the checked-in outputs, after generation completes.

```sh
uv run python -m tools.golden formats --check --report diff.json
uv run python -m tools.golden target --check
uv run python -m tools.golden --coverage
uv run python -m tools.golden all --authored --check --report authored-diff.json
uv run python -m tools.golden --authored-coverage
```

`--check` writes a fresh temporary tree and compares decoded documents (binary
files byte-for-byte). It exits nonzero for any changed output. `--report` lists
every changed field by file and case path. Without `--check`, outputs replace
the checked-in files. `--output DIR` writes a separate repository-shaped tree.

Generators exist for the components below; the rest of the test data is
checked in as recorded. `--coverage` lists every test data file, binary files
included, that has no declared generator, and exits nonzero while any remain.
`all --check` fails on the same files.
CI (`golden` in `.github/workflows/ci.yml`) checks every fully generated
component whole, then `all --authored --check` and `--authored-coverage`.

## Components

- `target`: ISA/operand snapshots, manifest and all native form records. The
  production tables themselves are generated by `tools.isagen` from the pinned
  AMD XML; these snapshots are evaluated from those tables and the native
  target API.
- `formats`: all nine files. Boundary inputs and seeded random streams are
  constructed in Python. `thin-formats` supplies Recipe, packing and MessagePack
  results through `cargo run -p thin-formats --example golden`. The generator
  does not implement encoding/rounding, packing or layout walking itself.
- `lib`: all six files. Constructors are Cartesian products and invalid-field
  perturbations. Clock buffers are built from synthetic 64-bit headers and lap
  samples. Program inputs are composed from reusable declaration/entry templates;
  observable traces come directly from settled native Builder instructions.
- `metron`: all ten files. Rank/median/verdict statistics and race plans use
  explicit edges and seeded timings. Tensor, pool and judging inputs share
  source constructors with the tests, never stored expectations. Kept kernels
  are compiled by `metron.maker`; compare outputs are recorded by CPU emulation.
  This component requires a torch-enabled environment (host tensors only).

- `dsl`: nine files of value, expression, control and memory snippets.
- `codegen`: seven source-bearing files, including seven executable kernels.
- `ir`: twelve program/constructor files, with native analysis examples and public API checks.
- `passes`: seven files of analysis programs and seeded allocation graphs.
- `opspec` and `runtime`: four and two files of executable scenarios, respectively.
- `emu_text` and `target_text`: two and three files of parser, claim and hazard programs.

## Authored-program scope

`--authored` selects only the files carrying hand-written input programs: DSL
and kernel source, IR and compiler-pass programs, parser/claim text, executable
operation/runtime scenarios, and library protocol programs. Input program plans
live in the generators. Expected artifacts and diagnostic text come from thin.

`tools/golden/authored.py` inventories this scope. `--authored-coverage` fails
on an unowned authored file or a newly discovered source-bearing file missing
from the inventory. It is a separate check, not an exemption: `--coverage`
still reports **every** unowned data file, including recorded numeric results,
encoding/target tables and format bytes. `all --check` keeps that strict rule;
`all --authored --check` checks the narrower program scope.

Numeric-only files outside the authored scope remain recorded. In authored
mode, the comparison layer also preserves the numeric-only `abi.json`
residency/budget tables and `target/hazards.json` delay-format table. Preservation
happens after fresh construction; these records are not generator inputs.
Full-generation checking does not acquire this scope exemption.
